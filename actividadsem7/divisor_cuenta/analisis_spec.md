Para cada porcentaje divido la cantidad de proposiciones de esa categoría entre las 70 analizadas y multiplico por 100. Las nueve proposiciones de los seis escenarios de aceptación (L031–L033, L047 y los dos efectos de L061 y L062) y de L080 viajan intactas: tocar un botón también es posible en React y la spec no prescribe Flutter. Cambiar «toca Calcular» por «activa Calcular» sería una mejora de redacción opcional, no una adaptación necesaria. Si hubiera enunciados MIXTOS, los reportaría aparte y no los sumaría al numerador CÓMO. El 30 % de contaminación es un umbral pedagógico de este deber, no una regla universal.

## 4. Posibles contradicciones tecnológicas

| Enunciado | Problema para React | Posible adaptación | Evidencia |
|---|---|---|---|
| Spec L031–L033, L047, L061–L062 y L080: «toca Calcular». | No hay contradicción tecnológica: también se puede tocar un botón en React. | Cambiar «toca Calcular» por «activa Calcular» sería una mejora de redacción opcional, no una adaptación necesaria de la spec. | La acción aparece literalmente en esos escenarios y en FR-003. No se ha creado ni probado aún una interfaz React. |
| Spec L086 y L104: funcionamiento completo sin conexión. | Si la interfaz React se entrega como sitio web, cargarla por primera vez podría requerir red. Eso pondría en duda la lectura más estricta de «completamente sin conexión», aunque el cálculo sea local. | Definir una entrega que permita abrir la interfaz sin red, además de mantener ingreso, selección y cálculo locales; comprobarlo cuando exista la versión React. | FR-009 exige no usar red ni base de datos; SC-005 exige las tres funciones sin conexión. La spec no describe cómo se distribuirá React. |
| Spec L017, L070 y L081: 2.345 se presenta como 2.35. | La implementación React podría no producir esa cifra si se confía en un redondeo predeterminado sin verificarlo. | Implementar y probar explícitamente la regla de empate indicada, usando el caso 2.345 → 2.35. | La aclaración L017 y FR-004 fijan el resultado; no hay evidencia todavía de una implementación React. |
| Constitution L007–L009 y L013–L014: «cada clase» y «clases de cálculo». | En React la solución puede organizarse con funciones y componentes; una regla limitada a clases dejaría fuera esas unidades. | Hablar de responsabilidades de cada unidad de código y de nuevas implementaciones de redondeo, sin exigir clases si no se usan. | Las reglas originales nombran clases, mientras la spec solo fija resultados y modos, no clases. |
| Constitution L018–L025: interfaces, tipo concreto, casts y clases consumidoras. | Si React se escribe sin interfaces formales, la formulación literal no identifica bien cómo comprobar sustitución y dependencias pequeñas. | Expresar el contrato de cada consumidor con las funciones, parámetros o tipos que realmente use el proyecto. | Esas palabras aparecen en L018–L025; ninguno de los tres archivos decide todavía entre JavaScript y TypeScript. |
| Constitution L029–L031 y L039: las dependencias concretas se inyectan desde `main.dart`. | `main.dart` pertenece al proyecto Flutter y no identifica el punto de composición de una aplicación React. | Conservar la inyección desde un único punto de composición y nombrar su archivo real cuando se cree el proyecto React. | La Constitution menciona `main.dart` en ambas reglas. Aún no existe un proyecto React cuyo archivo pueda citarse. |
| Constitution L037–L038: `lib/domain/` debe ser Dart puro y no importar `package:flutter`. | La ruta, el lenguaje y el paquete nombrados corresponden a Flutter; una prohibición literal de Flutter no basta para aislar el dominio en React. | Formular la regla para la carpeta y el lenguaje reales del nuevo proyecto y prohibir que el dominio dependa de componentes o APIs de la interfaz. | L037–L038 nombran explícitamente `lib/domain/`, Dart y `package:flutter`. |

No encuentro en la spec una regla de negocio que deba eliminarse por usar React. Las cuestiones anteriores muestran qué redacciones o decisiones de implementación exigirían atención; no prueban que ya exista una contradicción en una aplicación React.
